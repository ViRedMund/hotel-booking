# Hotel Booking API

REST API для управления гостиничными номерами и бронированиями. Проект разработан на Django REST Framework с использованием PostgreSQL.

## Возможности

### Гостиничные номера
- Создание гостиничных номеров.
- Получение списка всех номеров.
- Получение информации о конкретном номере.
- Удаление номера вместе со всеми связанными бронированиями.
- Сортировка номеров по цене и дате создания (по возрастанию и убыванию).

### Бронирования
- Создание бронирования для существующего номера.
- Получение списка бронирований конкретного номера.
- Сортировка бронирований по дате начала.
- Удаление бронирования.
- Валидация дат бронирования.

## Технологический стек

- Django 6.1
- Django REST Framework
- PostgreSQL 18
- Psycopg 3

- Poetry

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/ViRedMund/hotel-booking.git
cd hotel-booking
```

### 2. Установка зависимостей

Для установки зависимостей необходим Poetry.

```bash
poetry install
```

### 3. Настройка переменных окружения

Создайте файл `.env` в корневой директории проекта.

Пример содержимого:

```env
DB_HOST=localhost
DB_PORT=5432
DB_USER=hotel_app
DB_PASSWORD=your_password
DB_NAME=hotel_booking
```

Замените `your_password` на пароль пользователя PostgreSQL.

Файл `.env` не должен попадать в Git-репозиторий.

### 4. Настройка базы данных

Создайте базу данных PostgreSQL с именем `hotel_booking` и предоставьте пользователю `hotel_app` необходимые права доступа.

### 5. Применение миграций

```bash
poetry run python manage.py migrate
```

### 6. Запуск сервера

```bash
poetry run python manage.py runserver
```

После запуска API будет доступен по адресу:

```text
http://127.0.0.1:8000/
```

## API Documentation

Все запросы и ответы используют формат JSON.

### Гостиничные номера

| Метод | Endpoint | Описание |
|---|---|---|
| GET | `/api/hotels/` | Получить список номеров |
| POST | `/api/hotels/` | Создать номер |
| GET | `/api/hotels/{id}/` | Получить информацию о номере |
| DELETE | `/api/hotels/{id}/` | Удалить номер |

#### Получение списка номеров

```http
GET /api/hotels/
```

Поддерживается сортировка через query-параметр `ordering`.

Доступные значения:

| Параметр | Описание |
|---|---|
| `price_per_night` | Цена по возрастанию |
| `-price_per_night` | Цена по убыванию |
| `created_at` | Дата создания по возрастанию |
| `-created_at` | Дата создания по убыванию |

Пример:

```http
GET /api/hotels/?ordering=-price_per_night
```

#### Создание номера

```http
POST /api/hotels/
Content-Type: application/json
```

Тело запроса:

```json
{
    "description": "Deluxe room with sea view",
    "price_per_night": "4500.00"
}
```

Успешный ответ — `201 Created`:

```json
{
    "id": 1
}
```

#### Получение информации о номере

```http
GET /api/hotels/1/
```

Пример ответа:

```json
{
    "id": 1,
    "description": "Deluxe room with sea view",
    "price_per_night": "4500.00",
    "created_at": "2026-11-17T10:00:00Z"
}
```

#### Удаление номера

```http
DELETE /api/hotels/1/
```

Успешный ответ — `200 OK`:

```json
{
    "message": "Номер успешно удалён"
}
```

При удалении номера автоматически удаляются все связанные бронирования.

### Бронирования

| Метод | Endpoint | Описание |
|---|---|---|
| POST | `/api/bookings/` | Создать бронирование |
| DELETE | `/api/bookings/{id}/` | Удалить бронирование |
| GET | `/api/hotels/{room_id}/bookings/` | Получить бронирования номера |

#### Создание бронирования

```http
POST /api/bookings/
Content-Type: application/json
```

Тело запроса:

```json
{
    "date_from": "2026-12-10",
    "date_to": "2026-12-15",
    "room": 1
}
```

Параметры:

- `date_from` — дата начала бронирования.
- `date_to` — дата окончания бронирования.
- `room` — ID существующего гостиничного номера.

Формат дат: `YYYY-MM-DD`.

Дата окончания должна быть позже даты начала.

Успешный ответ — `201 Created`:

```json
{
    "booking_id": 1,
    "room_id": 1
}
```

#### Получение бронирований номера

```http
GET /api/hotels/1/bookings/
```

Бронирования возвращаются в порядке возрастания даты начала.

Пример ответа:

```json
[
    {
        "id": 1,
        "date_from": "2026-12-10",
        "date_to": "2026-12-15",
        "room": 1
    },
    {
        "id": 2,
        "date_from": "2026-12-20",
        "date_to": "2026-12-25",
        "room": 1
    }
]
```

#### Удаление бронирования

```http
DELETE /api/bookings/1/
```

Успешный ответ — `200 OK`:

```json
{
    "message": "Бронирование успешно удалёно"
}
```

## Обработка ошибок

API использует стандартные механизмы обработки ошибок Django REST Framework.

| HTTP-статус | Описание |
|---|---|
| 400 Bad Request | Ошибка валидации входящих данных |
| 404 Not Found | Запрашиваемый объект не найден |
| 405 Method Not Allowed | HTTP-метод не поддерживается |
| 201 Created | Объект успешно создан |
| 200 OK | Запрос успешно выполнен |

## Особенности реализации

- Для работы с базой данных используется Django ORM.
- Для преобразования и валидации данных используются DRF Serializers.
- Связь между гостиничными номерами и бронированиями реализована через `ForeignKey`.
- При удалении номера связанные бронирования удаляются каскадно (`on_delete=models.CASCADE`).
- Конфигурационные данные загружаются из `.env` с помощью Pydantic Settings.
- Проверяется существование номера при получении его бронирований.
- Проверяется корректность дат бронирования.

## Ограничения

- API не использует авторизацию.
- Проверка пересечения дат и доступности номеров не реализована.
- Одновременное бронирование одного номера разными клиентами не ограничивается.

## Запуск тестов

Для запуска автоматических тестов используется встроенный тестовый фреймворк Django и `APIClient` из Django REST Framework.

### Подготовка PostgreSQL

Django создаёт отдельную тестовую базу данных перед запуском тестов. Для этого пользователь PostgreSQL, указанный в `.env`, должен иметь право `CREATEDB`.

Подключитесь к PostgreSQL от имени администратора:

```bash
psql -U postgres -d postgres
```

Выдайте необходимые права пользователю базы данных:

```sql
ALTER USER hotel_app CREATEDB;
```

Замените `hotel_app` на имя пользователя PostgreSQL, указанное в вашем `.env`.

Выйдите из консоли PostgreSQL:

```sql
\q
```

### Запуск всех тестов

Из корневой директории проекта выполните:

```bash
poetry run python manage.py test
```

### Запуск тестов отдельных приложений

Тесты приложения `hotels`:

```bash
poetry run python manage.py test hotels
```

Тесты приложения `bookings`:

```bash
poetry run python manage.py test bookings
```

### Особенности тестирования

- Тесты проверяют создание, получение, сортировку и удаление номеров.
- Проверяется создание и удаление бронирований.
- Проверяется валидация дат бронирования.
- Проверяется получение списка бронирований конкретного номера.
- Проверяется обработка запросов к несуществующим объектам.
- Django автоматически создаёт отдельную тестовую базу данных и удаляет её после завершения тестирования.
- Основная база данных проекта не используется для хранения тестовых данных.
